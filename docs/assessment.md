# Atoms Demo 开发记录

## 我怎么用 Codex 做的

我先让 Codex 读题和 Atoms 的文档，定下第一条要跑通的路径：输入需求，拿到一个能在预览里操作的网页，再用一句话接着改。然后分开做：先实现生成接口和预览，再补项目对话、版本历史和浏览器保存。部署单独放到最后，出了问题可以先判断是应用行为还是线上环境的问题。

生成这块只用了一个 Agent。后端先让模型列几步构建计划，再让它写出 HTML、CSS 和 JavaScript。代码先过语法检查，然后在 iframe 里启动。后续修改会把当前版本的源码一并发给模型，新版本启动成功后才切过去。首版限定在单页应用，生成的网页跑在浏览器里，省掉了给每个生成物装依赖和启动服务的步骤。

## 我怎么部署的

本机 Wrangler 已登录 Cloudflare。在项目目录先跑 `npm run build:cloudflare`，用 OpenNext 把 Next.js 打包到 `.open-next/`，再跑 `npx wrangler deploy`，上传 Worker 和静态资源。Workers AI 绑定写在 `wrangler.jsonc` 里，上线后 Worker 通过它调用 Qwen。

## 我怎么验收的

本地先让 Codex 用固定响应跑浏览器测试，检查对话、版本切换、刷新恢复，以及新版本报错时老版本还能不能用。Wrangler 返回公网地址后，我单独用 Playwright 打开线上页面，跑了一遍真实生成。这条验收现在可以用 `npm run test:e2e` 重跑。

1. 让模型做一个排练室费用计算器，每小时 75 元。输入两小时，点「计算费用」，结果是 150 元。
2. 接着说「加一个会员八折选项」。勾选后同样输入两小时，结果是 120 元，取消勾选还是 150 元。
3. 刷新浏览器，从「最近项目」重新打开，确认对话和 v2 都还在。

第一次线上点计算没有反应。我让 Codex 取出生成的源码，发现表单已经绑了提交事件，是预览沙箱把事件拦住了。改完后用同一份源码复测，按钮能算出结果，浏览器仍会拦住表单向外提交。

## 现在能用到什么程度

线上可以直接试，无需注册。项目对话、源码和历史版本能在同一个浏览器里恢复，也能打开旧版或恢复它。生成应用里临时填的数据会随预览重载重置。跨设备同步、生成带后端的应用和自动验证生成物的功能都还没做。

## 后面先做什么

1. 让 Agent 给每个生成的应用写几条可执行的检查。第二轮修改后重跑这些检查，确认第一轮的功能还能不能用。
2. 再把预览里的错误带回对话。比如按钮点了没反应时，给 Agent 具体的操作和错误，让它有线索可修。修好后重跑同一条检查。
3. 最后考虑跨设备保存。等生成和修改稳定后，再把项目搬到服务端，方便换电脑继续编辑或把项目发给别人看。
